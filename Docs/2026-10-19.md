# AT·RT 용도 구분 및 검증

## 작업 내용

- Access Token에 ACCESS, Refresh Token에 REFRESH 용도를 나타내는 서명된 tokenType claim을 추가했습니다.
- JWT 인증 필터와 사용자·인증 컨트롤러의 Bearer 검증은 Access Token만 허용하도록 변경했습니다.
- 토큰 재발급 서비스는 Refresh Token만 허용하고, 용도가 다르면 저장소 조회 전에 거부하도록 변경했습니다.
- UUID를 통한 토큰 교환, RT Cookie 전달, Redis 원자적 RT Rotation은 유지했습니다.

## 변경 이유 및 근거 구분

- 명확: 기존 검증은 JWT 서명과 만료만 확인하고 AT·RT 용도를 구분하지 않았습니다.
- 명확: 기존 필터는 RT를 Bearer로 전달해도 인증 객체를 생성했습니다. 수정 전 회귀 테스트로 재현했습니다.
- 명확: 용도를 나타내는 claim은 JWT 서명에 포함되며, 누락되거나 알려지지 않은 값은 인증·재발급 경로에서 거부합니다.

## 영향 범위

- 신규 로그인 및 재발급으로 생성되는 모든 AT·RT에 용도 정보가 추가됩니다.
- 기존 tokenType 없는 토큰은 인증·재발급에 사용할 수 없으므로 배포 후 재로그인이 필요합니다.
- API 경로와 응답 Body, Cookie 정책은 변경하지 않았습니다.
- 일반 서명·만료 검증 메서드는 유지하되 실제 Bearer 인증과 재발급에서는 용도별 검증 메서드만 사용합니다.

## 검증 방법

- 수정 전 JWT 발급 claim, RT Bearer 인증 거부, AT 재발급 조기 거부 테스트 3개가 실패하는 것을 확인했습니다.
- JWT 단위 테스트로 용도별 정상·교차 검증, 용도 누락·알 수 없는 값, 만료·서명 오류·잘못된 입력을 확인합니다.
- 서비스·컨트롤러·필터 회귀 테스트로 기존 정상 인증과 RT Rotation 경로를 확인합니다.
- PostgreSQL·Redis Testcontainers 기반 통합 테스트로 RT를 이용한 보호 API 요청과 AT를 재발급 Cookie로 사용한 요청의 401 응답을 확인합니다.
- 전체 회귀 검증 명령은 ./gradlew test입니다.

## 검증 결과

- 수정 전 추가한 테스트 3개가 실패했고 수정 후 통과하여 문제 재현과 해결을 확인했습니다.
- IDE 빌드에 성공했습니다.
- 최초 전체 테스트는 Docker 미실행으로 통합 테스트 컨텍스트 초기화에 실패했습니다.
- Docker Desktop 실행 후 ./gradlew test --rerun-tasks로 전체 122개 테스트가 통과했습니다. 실패·오류·건너뜀은 모두 0건입니다.
- git diff --check를 통과했습니다.
